01 Executive Summary & Business Objectives

Academic institutions globally face an escalating challenge with fraudulent, tampered, or forged degree certificates and academic transcripts. Employers, foreign credential evaluation agencies (such as WES, IQAS, and ECCTIS), foreign licensing boards, and postgraduate admission offices require immediate, indisputable evidence of document authenticity.

This system introduces a state-of-the-art dual-tier verification architecture tailored specifically for the Faculty of Agriculture, Rajarata University of Sri Lanka:

1

Tier 1: Instant Online Verification (Public)

Enables anyone with the physical document or QR code to verify instantly whether the transcript is authentic, confirming the candidate's identity, conferred degree, effective graduation date, and Senate-approved GPA / Honours Classification.

2

Tier 2: Formal Verification Service (Restricted)

Protects confidential course-by-course module grades from public exposure while giving employers an expedited workflow to request an official, certified sealed verification report directly from the Senior Assistant Registrar (Examinations).

02 Core Verification Mechanism & Token Architecture

A common security concern when building verification portals is: "How does the system ensure that a token genuinely belongs to a specific student and transcript, rather than being forged or swapped?"

A. Document ID vs. Cryptographic Verification Token

Identifier Format Example Role & Visibility Security Mechanism
Document ID RUSL/FOA/2026/TR/042 Human-readable; printed on the transcript top-right corner. Used for manual typing. Unique composite key generated sequentially per faculty, year, and transcript registry.
Verification Token e7f1a94b802c6... (64-char SHA-256) Embedded invisibly inside the QR code URL. Never typed manually by users. Cryptographic hash of (Document_ID + Student_RegNo + Issued_Timestamp + Secret_Salt).
Student ID AG/2018/126 The student's permanent registration number in the Senate registry. Bound to the Document ID and Token at generation time; immutable once issued.
Bidirectional Integrity Check: When a user accesses the verification page (whether via QR code or manual input), the system performs a triple-validation:
  1. Does the Document ID exist in the transcript registry table?
  2. Does the token provided in the QR code exactly match the token stored in the database for that specific Document ID?
  3. Is the associated student record active and approved by the Faculty Senate?
Only if all three checks pass does the system retrieve and display the verified result.

04 Formal Verification Service & Application Form (Option 2)

When an employer, embassy, or evaluation service (e.g., WES) requires an official certified letter with a complete course breakdown, they click the "Download Application Form" button on the valid result page. This triggers an automated, standardized application generation workflow.

05 Deep Dive: The "Reference No. (For Office Use Only)"

At the bottom of the generated application form, the following line appears:

Document ID: RUSL/FOA/2026/TR/042  |  For office use only: Reference No. _______________

Stakeholders frequently ask: "What is the difference between the Document ID and the Reference Number?"

Document ID (The Student's Record)

Identifies the transcript itself. It was generated when the university printed the student's original transcript and never changes over time.

Reference No. (The Transaction File)

Identifies the incoming customer request. It is assigned by university office staff upon receiving the payment slip to track the processing lifecycle of that specific verification letter.

Lifecycle of the Reference Number in University Operations

  1. Applicant Submits: The employer fills Section B, deposits the fee at Bank of Ceylon, and emails the form and bank slip to sar@agri.rjt.ac.lk.
  2. Clerk Assigns Reference No.: The Examinations Division clerk opens an inward file and enters a reference number (e.g., RUSL/EXAM/VERIF/2026/104) into the university logbook.
  3. Accounts Reconciliation: University finance verifies the bank deposit using this reference number.
  4. Issuing the Official Letter: When the Senior Assistant Registrar signs the final official verification letter, this reference number is printed at the top ("Our Ref: RUSL/EXAM/VERIF/2026/104").
  5. Customer Inquiries: If the employer calls to inquire about status, both parties refer to this Reference Number for instant tracking.

06 Relational Database Architecture

The verification subsystem integrates cleanly with the existing examination database schema without disrupting student records, course units, or semester results:

Table Name Primary Key Key Fields & Foreign Keys Description
students id reg_no, index_no, full_name, degree_id Master Senate student registry.
transcripts id document_id (Unique), student_id, fgpa, class_id, issued_at Official transcript record created upon printing.
transcript_tokens id transcript_id, token_hash (Indexed), qr_code_path, status Stores the cryptographic hash embedded in the QR code.
verification_requests id reference_no (Unique), document_id, requester_org, payment_status Logs formal verification applications and payment slips.
verification_audit_logs id document_id_searched, ip_address, is_valid, created_at Security telemetry tracking lookups and potential fraudulent attempts.
